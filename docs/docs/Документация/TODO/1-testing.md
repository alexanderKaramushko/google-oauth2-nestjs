# 1. План ухода от id-токена Google и выпуска своих токенов с ассиметричной подписью

Сейчас есть проблема: id-токен Google продолжает использоваться после аутентификации.
Это прводит к тому, что приходится делать проверки токена через Google,
что приводит к:

- лишней зависимости от Google
- лишним запросам к SSO-клиенту

Какой профит перехода на свой токен:

- можно выдавать свой токен любому приложению
- снизить зависимость от стороннего провайдера
- можно заменить identity-провайдера в дальнейшем

## Алгоритм ухода от id-токена

1. Пользователь
2. Google OAuth
3. auth-service получает данные от Google
4. auth-service проверяет:
   "Google действительно аутентифицировал этого пользователя"
5. auth-service находит/создаёт пользователя в своей БД
6. auth-service выпускает СВОЙ JWT
   JWT подписывается PRIVATE KEY
7. JWT устанавливается приложению из appId
8. Пользователь делает запрос в другой сервиc
9. Другой сервис берёт JWT из cookie
10. Проверяет подпись через PUBLIC KEY
11. Получает sub из токена
12. сохраняет internal userId
